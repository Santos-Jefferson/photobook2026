h1. Photobook — Design, Architecture & UI

{info:title=One-liner}
Turn a user's library photos — or a single *Memory* — into a swipeable, AI‑narrated photo‑book story. Mobile‑first, presented as a full Capsyl‑style phone shell (Home · Explore · Photos · Memories · Library) and built on the Synchronoss *Genius Narration API*.
{info}

{toc:maxLevel=2|minLevel=2}

----

h2. 1. Product overview

Photobook takes a handful of photos and weaves them into an illustrated, narrated story the user can swipe through, translate, narrate aloud, edit photo‑by‑photo, save, and share. The app renders as a centered phone column at every screen size, so visiting the URL on a laptop feels exactly like the Capsyl mobile app.

*Two ways to create:*
* *One‑tap (frictionless):* open a *Memory* or multi‑select in *Photos* → tap *Create Photobook* → generates immediately with sensible defaults (*Retro Toons* style, *heartwarming* mood, *AI Storyteller*). EXIF date/place is folded in automatically.
* *From scratch (full control):* the *Creator* page — upload photos or *Choose from Photos* (the library) → AI *"What we noticed"* insights + auto‑suggested title/context → pick mood, art style, narrator perspective, stylize, and an optional *Bedtime story* mode → generate.

*Then:* swipe a full‑screen viewer with narration, translation and per‑photo editing → from the final page *Save*, *Share & export*, or *Edit photobook* (re‑generate with a new style + mood) → exports as PDF, self‑contained HTML, or a narrated 9:16 Stories video.

||Pillar||What it delivers||
|Home|Dashboard of Recent Photos, Favorites, Photobooks and Memories; global top bar (search · cloud‑upload · profile).|
|Photos|Capsyl‑style photo library (IndexedDB). Grid, favorites filter, multi‑select → *Create Photobook*, and a maximized detail view with a *Chat or book* entry point.|
|Explore → People|Face detection across the library (browser Shape Detection API); tag faces with names, grouped per person.|
|Memories|Capsyl‑style gallery of photo clusters. Open one → *Create Photobook* in a tap. (Creating a memory lives behind the user profile, since Capsyl has no "add memory" today.)|
|Generate|2–5 photos + vibe + image style + narrator perspective; EXIF date/place folded into the prompt. Returns opening · per‑photo caption + narrative · closing, with stylized images.|
|Insights & auto‑fill|"What we noticed" (themes, mood, highlight, people) plus AI‑suggested title + context, synthesized from the chosen photos.|
|Bedtime mode|Optionally retells the whole story gently, for reading to a child.|
|Narration|Neural TTS with selectable language and voice (gender) via a touch‑friendly bottom sheet.|
|Translate|Translate the whole story on the fly (internal LLM).|
|Perspective|Retell as AI storyteller / me / child / friend / parent (internal LLM).|
|Photo Chat|Per‑photo edits in natural language. On a standalone photo: one‑tap style presets (Retro Toons, Anime, Comic Book…) + quick edits (remove/blur background) + revert + on‑demand suggestions. In a story: text "memory actions" + Genius greeting cards.|
|Edit photobook|From the closing page, re‑generate the whole book with a new art style + mood (reuses the original photos).|

|Export & share|PDF (collage covers), self‑contained HTML (offline narration), narrated 9:16 Stories video, WhatsApp, Instagram cover.|

h2. 2. Design principles

* *Mobile‑only, by design* — the app is always a centered phone column, even on desktop, so everyone gets the Capsyl mobile experience behind a single URL. Full‑bleed imagery, thumb‑reachable controls, bottom sheets, safe‑area aware CTAs.
* *Feels like Capsyl* — real {{wl-icon}} glyphs in the bottom nav (Home · Explore · Photos · Memories · Library), the navy nav bar, teal active state, portrait Memory cards, the search/cloud/profile top bar.
* *One tap to delight* — a Memory or a Photos selection becomes a finished, narrated story in a single action; choices are reserved for the "from scratch" path.
* *Progressive, resilient* — gracefully falls back (browser TTS when the narration server is absent; original photo when no styled image returns; manual title/context when the analyze service is unreachable, with a visible notice).
* *Privacy by default* — photos and text only leave the browser to reach the Genius API and our own {{/api/*}} endpoints; saved books, memories, photos and people live locally in IndexedDB.

h3. Tech stack

* *Frontend:* React 18 + Vite 5, hand‑written CSS. Navigation is a small {{view}} state machine in {{App.jsx}} (no router). Overlays (search, profile, pickers) render via React portals to escape the sticky top bar's stacking context.
* *Backend:* a single Node {{http}} server ({{server/index.js}}) that serves the built SPA *and* the {{/api/*}} endpoints, sharing {{lib/narrate.js}}. For local development, an equivalent Vite middleware ({{vite.config.js}}) serves the same {{/api/*}} routes, so {{npm run dev}} runs the full app without a separate server.
* *AI / external:* *Genius Narration API* (photobook, photo‑chat, greeting cards, image stylization); *internal LLM (Qwen)* (translate, perspective, free‑form rewrite — which powers bedtime, insights and auto title/context); *msedge‑tts* (neural narration).
* *Browser libs:* {{exifr}} (EXIF/GPS), {{jspdf}} + {{html2canvas}} (PDF / IG cover), Canvas + {{MediaRecorder}} (in‑browser narrated video), browser Shape Detection {{FaceDetector}} (People).
* *Storage:* IndexedDB (saved books, memories, photo library, people) + localStorage (display name, optional API settings).

h3. Generation data flow

# Photos come from the *Photos* library or *Memory* (already JPEG data URLs with stored EXIF), or from the *Creator* (uploaded {{File}}s, EXIF read before re‑encode, or picked from the library).
# {{buildPayload}} assembles {{{ photos, vibe, style, stylize_images, title, context, perspective }}} and POSTs it to the Genius *photobook* endpoint (Bearer auth). The quick paths use defaults; the Creator uses the chosen options.
# {{normalizeBook}} unwraps the response and flags truncation; uploaded/original photos are kept as fallbacks (and enable *Edit photobook* re‑generation later).
# The story is optionally *retold in the chosen perspective* and/or softened into a *bedtime* read via the internal LLM.
# {{StoryViewer}} renders slides; narration, translation, insights and per‑photo edits are fetched on demand.

h2. 4. Deployment (Bitbucket → Bamboo → Kubernetes)

* *Source control:* Bitbucket / Stash.
* *CI/CD:* a *Bamboo* plan builds the multi‑stage Docker image ({{Dockerfile}}: {{npm ci}} + {{vite build}} → slim Node runtime with production deps only), tags it from {{.release_number}}, and deploys to *Kubernetes* via the Helm chart under {{deployment/helm}} ({{.helm_release_number}}). Build/dockerize/deploy steps are wired through the {{Makefile}}.
* *Runtime:* a single container runs {{node server/index.js}}, serving the built {{dist/}} SPA *and* the {{/api/*}} endpoints. Kubernetes liveness/readiness use {{GET /healthz}}.
* *Config:* client config (Genius API URL/key) is baked at build time via Vite env vars ({{VITE_PHOTOBOOK_API_URL}}, {{VITE_PHOTOBOOK_API_KEY}}); the internal LLM endpoint is overridable via {{TRANSLATE_API_URL}} / {{TRANSLATE_MODEL}}; narration needs the msedge‑tts dependency reachable from the pod.
* *Local dev:* {{npm run dev}} (Vite, with the {{/api/*}} middleware) for the full app, or {{npm run share}} (build + Node server) to mirror production.

h2. 7. Roadmap

* Native Capsyl *Memories* integration — pull real Memory clusters instead of uploading.
* *People*: true cross‑photo face *recognition* (embeddings) for automatic same‑person grouping, beyond browser face detection + manual naming.
* Album insights surfaced inside the saved book / shared video; richer greeting‑card composition.
* Mobile packaging — installable *PWA* and/or a thin *Capacitor* Android shell over the deployed URL.
* Server‑side persistence and premium TTS voices (SLA).
